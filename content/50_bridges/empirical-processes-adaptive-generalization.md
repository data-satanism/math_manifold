# Эмпирические процессы → равномерное и адаптивное обобщение

## Математическая структура

Для класса потерь

$$
\mathcal L
=
\{\ell_f:f\in\mathcal F\}
$$

равномерный разрыв риска:

$$
\Delta_n(\mathcal F)
=
\sup_{f\in\mathcal F}
|\widehat R_n(f)-R(f)|.
$$

Если алгоритм выбирает $\widehat f\in\mathcal F$ по обучающей выборке, то

$$
|\widehat R_n(\widehat f)-R(\widehat f)|
\le
\Delta_n(\mathcal F).
$$

Так равномерная граница законно покрывает адаптивный выбор внутри заранее определённого класса.

## Понятный образ: сертифицированный каталог

Контролёр не знает заранее, какой режим выберет оператор, поэтому проверяет не один режим, а весь разрешённый каталог. Если каталог расширяют после просмотра результатов контроля, старый сертификат больше не покрывает новую процедуру.

Это **`analogy`**.

## Перенос в ИИ

### Установлено

Симметризация, сложность Радемахера и VC-размерность дают границы для выбора модели внутри фиксированного класса при заявленных предпосылках. Это **`established`**.

### Адаптивный перебор

Реальная процедура часто включает:

- выбор архитектуры;
- подбор признаков;
- настройку порогов;
- повторный просмотр проверочной выборки;
- выбор лучшего из нескольких случайных запусков.

Полный класс решений должен включать все эти ветви. Граница только для финальной архитектуры не оплачивает предыдущий поиск.

### Исследовательская гипотеза

Журнал решений можно преобразовать в явное дерево выбора и оценивать сложность всей процедуры, а не только итоговой модели. Это **`research hypothesis`**.

## Практический протокол

1. До проверки описать пространство допустимых решений.
2. Разделить данные для обучения, выбора и окончательного аудита.
3. Учитывать число и зависимость повторных обращений к проверочному набору.
4. Хранить журнал архитектур, порогов и критериев выбора.
5. После изменения процедуры считать старую гарантию недействительной до новой оценки.

## Режимы отказа

1. Класс объявляется постфактум вокруг выбранной модели.
2. Проверочная выборка многократно используется для принятия решений.
3. Зависимые временные окна анализируются как независимые объекты.
4. Средняя граница по запускам выдаётся за гарантию конкретного выбранного запуска.

## Вычислительная схема

```python
def audit_search_space(model_cards):
    return {
        "architectures": len({m["architecture"] for m in model_cards}),
        "thresholds": len({m["threshold"] for m in model_cards}),
        "seeds": len({m["seed"] for m in model_cards}),
        "validation_queries": len(model_cards),
    }
```

Это инвентаризация адаптивности, а не сама вероятностная граница.
